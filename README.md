# 0x00 SPACE Publisher

UserBot на базе Telethon читает новые текстовые посты, фото или видео из выбранного
Telegram-канала от имени вашего личного аккаунта (администраторство в источнике не
требуется),
адаптирует текст через Gemini и присылает его владельцу с кнопками **«Опубликовать»**
и **«Отклонить»**. После нажатия публикация отправляется в канал `TARGET_CHANNEL`.

Текст оформляется в HTML-стиле Telegram: выделенный заголовок, курсивное название,
блок «ПОДРОБНЕЕ О ДОПОЛНЕНИИ», кликабельная ссылка, версии и хэштеги.
Ссылка на оригинальный пост источника добавляется автоматически, даже если в тексте
исходного сообщения её не было.

## Быстрый запуск

1. Создайте бота через `@BotFather` и скопируйте токен.
2. Получите `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` на
   [my.telegram.org](https://my.telegram.org), приложение **API development tools**.
3. Получите ключ Gemini в Google AI Studio.
4. Скопируйте `.env.example` в `.env` и заполните значения.
   `ADMIN_USER_ID` можно узнать командой `/id` у бота.
5. Добавьте личный аккаунт в исходный канал как подписчика. Администраторские права
   ему не нужны. Бот должен быть администратором только в `TARGET_CHANNEL` с правом
   публикации.
6. Установите зависимости и запустите:

```bash
python -m venv .venv
# Windows PowerShell
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python bot.py
```

Для запуска тестов установите dev-зависимости и выполните:

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

При первом запуске Telethon попросит номер телефона, код из Telegram и, если включён,
пароль двухфакторной аутентификации. Сессия сохранится в `TELETHON_SESSION`, поэтому
повторно входить обычно не потребуется.

Чтобы обработать не новые, а последние сообщения канала, отправьте боту команду
`/last5`, выберите источник и количество: 1, 3 или 5 постов. Черновики будут созданы
от старого сообщения к новому. Команду может
использовать только `ADMIN_USER_ID`.

Источниками можно управлять прямо в Telegram:

- `/sources` — открыть панель источников;
- `/addsource @channel` — добавить публичный канал, на который подписан личный аккаунт;
  можно также отправить `/addsource`, а затем прислать ссылку отдельным сообщением;
- кнопки в панели позволяют включать/выключать источник, удалять его и загружать
  пять последних постов именно из выбранного канала.
- кнопка `⚙️` открывает настройки фильтра, промпта и автопубликации.
- список источников листается кнопками `⬅️` и `➡️`.
- предпросмотр фото и видео отправляется вместе с текстом и кнопками модерации;

Новые посты автоматически обрабатываются только из включённых источников. Доступные
команды также отображаются в меню бота: `/start`, `/sources`, `/addsource`, `/last5`,
`/stats`, `/edit`, `/retry`, `/schedule`, `/id` и `/help`.

Дополнительные возможности:

- одинаковый пост не обрабатывается повторно после перезапуска;
- обработка постов выполняется последовательно через очередь;
- поддерживаются фото, видео, документы, аудио, голосовые сообщения и GIF;
- фото- и видеоальбомы сохраняются как одна публикация;
- файлы без подписи (например `.mcaddon`, `.zip`, `.jar`) также обрабатываются и
  публикуются с автоматически созданным описанием;
- файл мода, отправленный сразу после поста, автоматически прикрепляется к его
  черновику и публикуется вместе с ним;
- `/stats` показывает статистику, эффективность публикаций и разбивку по источникам;
- `/edit ID новый текст` изменяет черновик;
- `/retry ID` повторно отправляет исходный текст в Gemini;
- `/schedule ID YYYY-MM-DD HH:MM` планирует публикацию (время UTC).
- При ошибке обработки администратор получает уведомление в Telegram.
- `/setkeywords ID слово1,слово2` задаёт фильтр ключевых слов для источника;
- `/setprompt ID текст` задаёт дополнительные правила Gemini для источника;
- `/autopublish ID on|off` включает или выключает публикацию без модерации.
- `/history` показывает историю черновиков;
- `/cancel ID` отменяет запланированную публикацию;
- `/target ID @channel` выбирает канал назначения для черновика;
- `/cleanup 30` удаляет обработанные записи старше 30 дней.
- При выполнении `/last5` бот показывает прогресс: «обработано N из 5».
- `/history` позволяет повторно опубликовать старую запись кнопкой.
- `/refreshsources` обновляет названия каналов в панели.
- `/force ID` принудительно повторно обрабатывает уже пропущенный пост;
- `/search слово` ищет посты в истории.
- Локальная панель открывается в браузере по адресу `http://127.0.0.1:8080`.

Планировщик использует часовой пояс из `TIMEZONE` (по умолчанию `Europe/Moscow` в
шаблоне `.env`).

Для нескольких администраторов укажите их ID через запятую в `ADMIN_USER_IDS`.
`TEST_MODE=1` отправляет публикации только администратору вместо канала назначения.
Нежелательные слова можно указать в `BLOCKED_KEYWORDS` через запятую. Логи пишутся
в `LOG_PATH`. Максимальный размер медиа задаётся в `MAX_MEDIA_MB`. Дополнительно
доступны `BLOCKED_LINK_DOMAINS`, `REQUIRED_HASHTAGS`, `BLOCKED_AUTHOR_IDS` и
`BLOCKED_EXTENSIONS`.
Веб-панель привязана к `127.0.0.1` и не доступна из интернета.
Одинаковые тексты из разных каналов также отфильтровываются.

## Развёртывание на Render

В проект уже добавлен `render.yaml`. Для постоянной работы выбирайте **Web Service**
из этого Blueprint (это также запускает Telegram long polling). Persistent Disk нужен
для SQLite и файлов сессии; на бесплатном тарифе Render сервис может засыпать и данные
не сохраняются.

1. Загрузите проект в GitHub, затем в Render выберите **New → Blueprint** и этот репозиторий.
2. Заполните секретные переменные `BOT_TOKEN`, `GEMINI_API_KEY`, `ADMIN_USER_ID`,
   `ADMIN_USER_IDS`, `SOURCE_CHANNEL`, `TARGET_CHANNEL`, `TELEGRAM_API_ID`,
   `TELEGRAM_API_HASH` и `TELETHON_SESSION_STRING`.
3. Добавьте бота администратором в `TARGET_CHANNEL`. Личный Telegram-аккаунт,
   использованный для Telethon, должен быть подписан на `SOURCE_CHANNEL`.
4. После деплоя откройте URL Render: корень `/` покажет панель состояния.

`TELETHON_SESSION_STRING` надо получить локально один раз. Установите зависимости,
задайте локально `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`, затем выполните
`python generate_session.py`, введите номер, код и 2FA и сохраните напечатанную строку
только в Render Environment Variables. Файлы `.env` и
`*.session` в GitHub загружать нельзя. При публикации уже раскрытых ключей из локального
`.env` обязательно перевыпустите токен бота и ключ Gemini.

Для публичного канала укажите `@username`. Для приватного используйте числовой
ID вида `-100...`; личный аккаунт должен состоять в этом канале.

## Важно

- Не передавайте файл сессии (`data/userbot.session`) и значения `.env` третьим лицам.
- Черновики сохраняются в SQLite и не пропадут при перезапуске до обработки.
- Никому не показывайте `.env`: в нём находятся токены и ключ Gemini.
- Для планировщика процесс бота должен постоянно работать.
- Время планировщика указывается в UTC.
